1. How many strategies are in Session 4?

8 cleaning strategies, made of 27 named techniques. The lesson's own closing list names the eight stages: normalization, format discipline, quality filtering, deduplication, language validation, PII removal, decontamination and the manifest. Extraction comes before them, but it was taught in Session 3, so it is not counted here. Inside each stage the lesson names specific techniques. I counted one technique wherever the text describes a separate rule or mechanism.

1NormalizationSection 3 · 5
  • Unicode NFC — one byte encoding for every character
  • Strip invisible noise — zero-width space, byte-order mark, bidi overrides, control characters
  • Keep ZWJ and ZWNJ — they carry meaning in Brahmic scripts, so they are never removed
  • Unescape HTML entities — &amp; becomes &
  • Collapse whitespace — runs of spaces and blank lines
2One conversation formatSection 4, ghost tags · 2
  • One canonical format — rewrite every source into one structure at ingestion
  • Real special tokens — never literal [INST] or <|im_start|> text in pre-training
3Quality filteringSection 5 · 6
  • Average word length — heuristic rule
  • Symbol-to-word ratio — heuristic rule
  • Lines ending in punctuation — heuristic rule
  • Duplicated lines — heuristic rule
  • Stop-word presence — heuristic rule
  • Educational-value classifier — a large model labels a sample, a light model imitates it at scale
4DeduplicationSections 6 and 7 · 4
  • Exact deduplication — content hash
  • Shingling + MinHash — estimate the Jaccard overlap from short signatures
  • LSH banding — compare only documents that share a band
  • Global, not local — one central large-memory machine sees every shard
5Language identificationSection 8 · 2
  • Detect at runtime — never trust the folder name
  • Validate codes, fail loudly — the Telugu te/tel bug
6PII removalSection 9 · 2
  • Regex layer — emails, phone numbers, IP addresses
  • ML layer — personal names; precision against recall, hardest for Indic names
7DecontaminationSection 10 · 3
  • Fingerprint the eval sets — n-gram fingerprints
  • Scan and remove overlaps — every shard, against every benchmark
  • Canary strings — detect a leak after the fact
8Reproducibility and manifestSection 11 · 3
  • Deterministic content-based ids — never a running counter
  • Hash after cleaning — the hash describes the clean text
  • Provenance manifest + licence gate — source, licence, script hash, tokens, languages; unknown licence is blocked

2. The dataset I picked

lordx64/reasoning-distill-opus-4-7-max-sftApache-2.0 · 29.3 MB · 7,823 rows

The assignment links the model Qwen3.6-35B-A3B-Claude-4.7-Opus-Reasoning-Distilled. Its card names the dataset it was trained on, so I cleaned that exact dataset: https://huggingface.co/datasets/lordx64/reasoning-distill-opus-4-7-max-sft. It holds single-turn conversations whose answers, with their <think> reasoning, were generated by Claude Opus 4.7. The prompts were reused from earlier distillation corpora (competitive programming, maths, translation, reading comprehension and open chat).

Why this one: it is 29 MB, inside the 10–100M range. It is the data behind the example, and it is exactly the kind of post-training data V5 will need for its reasoning and agentic slots. It is also dirty in the ways Session 4 is about: ghost chat markers in every row, mojibake, duplicates and prompts with no task.

Why. Every row is one string with literal Qwen markers: <|im_start|>user … <|im_end|> and <think>…</think>. Trained on as text, those markers are exactly the ghost tags of Section 4: the model learns them as ordinary subwords and later fights the real special tokens.

How. Parse each row into messages[{role, content}] plus a separate reasoning field. Rows whose markers do not parse, or that still contain any other format's markers ([INST], ### Human:, <start_of_turn>…) inside the text, are dropped. 1,179 rows have no <think> block at all: they are valid answers, so they are kept and labelled has_reasoning: false rather than silently mixed in.

quality7,822 → 7,615 rows · −207 removed

Why. English web heuristics (symbol ratio, stop words, punctuation) are wrong for chat data full of code and maths, so the filters were rewritten for what goes wrong in distilled reasoning data.

How. Drop: prompts that are only boilerplate with no task (the answer just asks for the missing problem), prompts under 15 characters ("# Problem"), empty <think> blocks, empty answers, answers with an unclosed code block (truncated), answers with more than 30% duplicated lines, and degenerate loops of 32+ repeated 4-grams (the OLMo 2 rule). One-letter answers like "C" are kept: they are correct answers to multiple-choice questions.

Why. Benchmark questions hidden in the training data would make every later score dishonest.

How. Every 13-gram of GSM8K test (1,319), HumanEval (164) and MATH-500 (500) is indexed; every row is scanned and any row sharing a 13-gram is removed.

Harm testPASS

The medicine must not damage good text. I ran the same normalization and PII scrubbing on 307 known-good documents: the Session 2 English and Hindi Wikipedia paragraphs, Telugu, Malayalam, Hindi and Bengali strings that use ZWJ/ZWNJ, an emoji ZWJ sequence, and code blocks.

  • Harmful changes: 0 (0.0%), under the 1% limit.
  • Documents changed at all: 5 (1.629%). Every one was real dirt being fixed: byte-order mark removed ×2, html entities unescaped (prose only) ×5.
  • ZWJ/ZWNJ before → after: 19 → 19, so none were removed.
  • Code blocks byte-exact: True.
The first version failed: a "collapse runs of spaces" rule changed 9.1% of the good documents (Markdown tables, double spaces after full stops). The harm test caught it, and the rule was removed.

4. Other strategies and concerns

  • Licence of distilled outputs. The card says Apache-2.0, but the answers are generated by a commercial model, and its provider's terms restrict using outputs to train competing models. Before V5 trains on this, it needs a legal check, not just a licence field. The manifest records it as a concern.
  • Mixed formats. 1,118 of the kept rows answer without any <think> block. Mixing them silently would teach the model to sometimes skip reasoning, so they are kept but labelled, and the SFT mixture can choose.
  • The language label is wrong. The card says English, but 622 rows are not plain English (other scripts, or code-heavy). Counting them as English would skew the Session 5 mixture.
  • No ML name detection. Only the regex PII layer ran: no NER model was available offline. Names in prompts (mostly public figures and fictional characters) are untouched, and that is a known gap.
  • Decontamination coverage. Zero overlaps at 13-grams against GSM8K, HumanEval and MATH-500. That does not prove the data is clean for every benchmark: MMLU, LiveCodeBench and the Indic sets were not scanned, and paraphrased leaks escape exact n-grams.
  • English quality heuristics do not fit. Symbol-ratio and stop-word rules would have thrown away most of the code and maths, so they were replaced with chat-specific rules. This is Section 5's filter-bias warning, in a different form.
  • Near-duplicate policy. When a prompt appears more than once, only the fullest answer is kept. For preference data you would keep both and pair them instead.
