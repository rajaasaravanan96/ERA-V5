# ERA V5 · Session 5 — the V5 mixture and curriculum plan

A specification meant to be argued with. Every share below is sized against the **course's Session 5 dataset
inventory**: the real unique tokens of each source. The table in **What the numbers cost** is generated by
[`plan_check.py`](plan_check.py) (`python plan_check.py` writes [`plan_tables.md`](plan_tables.md)). So when a reviewer
changes a number, the epochs and the synthetic share recompute.

**Target model.** V5 is ~27–30B parameters. It must be:
1. best at **code and agentic work** (first priority);
2. a **reasoning model with an effort dial**;
3. **native in Indic languages**.

**Budget.** 14.25T tokens of main pretraining (inside the 10–30T range from Session 3, ~500 tokens per parameter),
plus a **0.30T anneal** held in reserve. The plan is a set of shares, so if the budget moves, the shares stay and
`plan_check.py` re-derives the repetition.

**Rule for repetition.** At most **4 epochs of any real source**. Beyond ~4 epochs, repeated data is worth much less
than fresh data (Muennighoff et al., 2023, *Scaling Data-Constrained LMs*). Anything a lane needs beyond 4 epochs
must be generated, and this plan says so lane by lane.

## 1. The lanes, the benchmarks they must win, and why each share is what it is

| lane | share of main run | wins (benchmarks) | why this number |
|---|---|---|---|
| **code** | **26.2%** | HumanEval+/MBPP+, LiveCodeBench, SWE-bench Verified (with agentic), Aider Polyglot | First priority. 4 epochs of the 859B unique Stack v2 + commits = 3.4T. It is capped there, plus 8% verified synthetic code (unit-tested rewrites and explanations). Going higher means synthetic code dominates the lane. |
| **general web** | **55.1%** | MMLU-Pro, world knowledge; the base that every other skill reads with | The only lane with real supply to spare: 3.8T unique for 7.9T needed is **2.05 epochs**, no synthesis. It falls from 67% to 45% across the stages, as V4's did (70% → 18%). |
| **maths & reasoning** | **5.6%** | GSM8K, MATH-500, AIME (and, after RL, the effort dial) | Real supply is thin (AON 78B, minus a 10% hold-back). 4 epochs give 281B, so **514B (65%) must be generated**: rephrased maths web plus generated problems **with checked answers**. The long CoT traces are not spent here at all (see the reserve). |
| **Indic** | **7.4%** | IndicXTREME, MILU, IndicGenBench, FLORES-200 (en↔xx), native human eval | V4 protected 8%. Section 2 shows why 7.4% is the honest ceiling: higher, and the synthetic share passes a third. |
| **STEM papers** | **3.4%** | GPQA, SciQ, MMLU-STEM | peS2o + proof-pile-2 = 97B unique, at 4 epochs + 100B rephrased (20%). |
| **long context** | **1.3%** (8% of stage 3) | RULER, LongBench v2, repo-level SWE tasks | Only in stage 3 (32K context). 100B unique at 1.8 epochs. Repo-packed code makes up 60% of the lane, because long context exists to serve the agent. |
| **agentic-shaped** | **1.0%** | τ²-bench, BFCL, Terminal-Bench (after SFT/RL) | **There is almost no agentic data**: the entire inventory is **0.63B tokens**. Spent in pretraining, 1% would be 230 epochs. So in pretraining this lane is CommitPack diffs (4B, 4 epochs) plus **126B generated** "agent-shaped" text (89%). The 0.63B of real trajectories is never spent in pretraining: it goes to the anneal and SFT. |

**Coding-first, counted honestly.** Code is 26.2%. Code-adjacent tokens (agentic-shaped, the code half of long context,
and the code-heavy part of reasoning) add another ~3%. So ~30% of the main run serves the first priority, and the
anneal raises code to 30% of its tokens.

## 2. The Indic lane, split by provenance tier

The Indic lane is 1,058B tokens. The real unique supply is **113.9B in total**: 51.2B verified after the hold-back,
44.9B unverified, 5B parallel, and 162B is Sangraha's synthetic expansion.

| tier | share of Indic | tokens | sources | real unique | epochs | generated / translated |
|---|---|---|---|---|---|---|
| **verified** (tier A) | **30%** | 317B | Sangraha verified (80% of it; 20% held back) | 51.2B | 4.0 | **112B**: new native text (the TSAI collection drive, government and court data, Prasar Bharati, Wikipedia native edits) |
| **unverified** (tier B) | **20%** | 212B | Sangraha unverified, IndicCorpV2 | 44.9B | 4.0 | 32B |
| **translated** (tier C) | **20%** | 212B | BPCC, Samanantar | 5.0B | 4.0 | **192B**: machine translation of FineWeb-Edu STEM and code documentation into the top 10 Indic languages, filtered by round-trip quality |
| **synthetic** (tier C) | **30%** | 317B | Sangraha synthetic | 162B | 1.96 | 0 |

Native text (verified + unverified) is **half** of the Indic lane. Synthetic + translated is the other half, and it is
**capped at 50%**. This is the main argument against a bigger headline number:

- At **10% Indic** (1.43T), the same verified and unverified tiers at 4 epochs cover only 23% of the lane, and synthetic + translated rise to **77%**.
- The model would learn translationese and the habits of the generating model, not the language.

So the plan holds the lane at 7.4% and puts the effort where it pays:
1. **More verified text**: the 112B gap is a collection target for the data teams, not a number to fill quietly.
2. **The anneal**: the best held-back verified Indic is spent there, at 15% of the anneal.

## 3. The protected always-on floor

OPUS (or any selector) chooses the remaining 91% of every batch. **9% of every batch is outside its control:**

| floor | % of every batch | why the selector would starve it |
|---|---|---|
| Indic, **verified + unverified only** (never synthetic) | 5.0% | An English-heavy proxy scores native Indic text as off-distribution (Section 8 of the lesson). |
| maths & reasoning (AON) | 2.5% | Long derivations score as low-perplexity and boring to a web-trained proxy. |
| agentic-shaped (commits and diffs) | 0.5% | Diffs look like noise to a prose proxy. |
| benchmark **train** splits, for format familiarity only | 1.0% | The same as V4's always-on lane. Test splits never enter: they are the golden proxy. |

The floor is a **minimum**. OPUS may add more of any of these lanes, and it may never give less. This 9% is part of the stage
shares above, not on top of them: Indic is 7.4% in total, of which 5% is guaranteed.

## 4. The curriculum: stages, contexts and blends

| stage | tokens | context | general web | STEM | code | maths & reasoning | Indic | long ctx | agentic-shaped |
|---|---|---|---|---|---|---|---|---|---|
| 1 foundation | 6.00T | 4K | 67% | 3% | 18% | 4% | 7.5% | 0% | 0.5% |
| 2 code + reasoning | 6.00T | 8K | 47% | 4% | 33% | 7% | 7.5% | 0% | 1.5% |
| 3 long context | 2.25T | 32K | 45% | 3% | 30% | 6% | 7% | 8% | 1% |
| **whole main run** | **14.25T** | | **55.1%** | **3.4%** | **26.2%** | **5.6%** | **7.4%** | **1.3%** | **1.0%** |
| 4 anneal (reserve) | 0.30T | 32K | 25% top slice | — | 30% | 20% | 15% | 5% | 5% (real trajectories) |

**Transitions are blended, never switched.** Every stage boundary is a linear blend over **50B tokens**, so the
mixture never jumps. This is V4's rule, after its Hindi-share jump hit frozen embeddings and the grad norm rose 150×.
During each blend, the grad norm and the per-lane loss are watched with the Session 15 alerts.

Why this order:
- Stage 1 builds language and knowledge while the model cannot yet use hard code or long proofs.
- Stage 2 shifts toward code and reasoning once the base exists.
- Long context comes last, when the model already reads well, so 32K training only has to teach *retrieval over distance*.
- Indic stays nearly constant across all stages. Moving it is exactly what broke V4.

## 6. Difficulty bands, with one example each

Used to order the data inside the maths/reasoning and code lanes: easier first, harder later, and the hardest saved for stage 2 and the anneal.

| band | maths example | code example |
|---|---|---|
| **D1 basic** | "A shop sells pens at ₹12 each. Riya buys 7 and pays with ₹100. How much change?" (one step) | "Write `is_palindrome(s)` ignoring case." (MBPP-level) |
| **D2 school / standard** | "Find all real x with x² − 5x + 6 ≤ 0." (one technique) | "Return the k most frequent words in a list, ties broken alphabetically." |
| **D3 competition** | "How many positive integers n ≤ 1000 make n² + n + 41 composite?" (AMC/AIME style) | "Codeforces Div2 C: minimum operations to make an array non-decreasing with prefix increments." |
| **D4 research / repo** | "Prove that every finite group of order p² is abelian." | "Fix this failing test in a 40-file repository, where the bug is in a different module from the failing assertion." (SWE-bench style) |

## 7. Reasoning-length bands, for the effort dial

The SFT/RL reasoning data (Sessions 17–18) is drawn from the reserve in four length bands. The model can only obey
an effort setting it has seen examples of.

| band | thinking tokens | share of reasoning SFT | example |
|---|---|---|---|
| **low** | < 256 | 35% | "What is 17 × 24?" → "17 × 24 = 17 × 25 − 17 = 408." |
| **medium** | 256 – 2K | 35% | A GSM8K word problem: set up the quantities, compute, check the units. |
| **high** | 2K – 8K | 20% | An AIME problem: try two approaches, verify the answer with a small case before committing. |
| **ultra** | 8K – 32K | 10% | A Codeforces Div1 D: derive the algorithm, write a brute force, cross-check on random tests, fix the edge case, then answer. |

## 8. The plan as a hypothesis: the proxy experiment

Nothing above is trusted until it survives this.

**Arms**, each a **1B dense model, 25B tokens** (20 tokens per parameter), with the same tokenizer, the same 25B
sampled by the stage schedule scaled down, and the same seed:

| arm | change from the plan | the question it answers |
|---|---|---|
| **A: the plan** | — | baseline |
| B: more Indic | Indic 10% with 77% synthetic + translated | Does more (mostly synthetic) Indic beat 7.4% mostly-native Indic? |
| C: more code | code 35%, general web 46% | Does coding-first cost too much knowledge and reasoning? |
| D: no floor | the selector controls 100% of every batch | Does the protected floor matter at this scale? |

**Metrics, chosen to be tokenizer-independent and stable at 1B:**
1. **Bits per byte** on held-out sets, per lane: Sangraha-verified held-out (10 languages, per language), FLORES-200 devtest
   (native side), held-out Stack v2 repositories, GSM8K/MATH *solutions*, FineWeb-Edu held-out.
2. HumanEval+ pass@10 and MBPP+ pass@10 (measurable at 1B; pass@1 is noise).
3. The grad-norm spike score at each stage blend (Session 15's 7σ rule), so the curriculum is tested, not only the mixture.

**What would confirm the plan, written down before the run:**
- **A against B:** A's mean Indic BPB is ≤ B's **on the verified held-out set**. If B wins by > 2% there, the Indic share goes up and the synthetic cap moves.
- **A against C:** A's code BPB is within 1.5% of C's while its general and reasoning BPB are ≥ 2% better. If C's code gain is > 3% with < 1% loss elsewhere, code goes to 30%.
- **A against D:** A's Indic BPB is ≥ 3% better than D's. If D matches A, the floor is not needed at this scale (and the 3B run must re-check it).
- **Curriculum:** no stage blend produces a spike score > 7σ.

**Then at 3B:** the plan and the best challenger, **60B tokens each**, on the same metrics plus IndicGenBench and
LiveCodeBench-easy. A share is frozen only if the 1B and the 3B result agree.

**Cost:**
- 1B × 25B tokens = 6 × 1e9 × 25e9 = **1.5e20 FLOPs per arm**, about **105 H100-hours** at 40% MFU. Four arms ≈ **420 H100-hours**, about 2.2 days on one 8-GPU node.
- 3B × 60B = 1.1e21 FLOPs per arm, ≈ **750 H100-hours each**; two arms ≈ 8 days on one node.

## 9. What I am asking the data teams for (the starved lanes)

| gap | size | why it is the biggest risk |
|---|---|---|
| verified Indic native text | 112B | it is the protected lane, and right now it can only be filled by repetition |
| Indic translation of STEM + code docs, round-trip filtered | 192B | the translated tier has only 5B of real parallel text |
| verified maths problems with checked answers | 514B | 65% of the maths lane is synthetic: it must be *checked*, not just generated |
| agent-shaped code text + executable trajectories | 126B + more real trajectories | the whole inventory has 0.63B agentic tokens |

These are the slots the cleaning work should now aim at. Every other lane can be filled from real supply within 4 epochs.
